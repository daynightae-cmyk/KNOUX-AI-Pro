**التاريخ:** 2026-11-16. **قرار المالك الحالي:** Visual Production أولًا، End-to-End وAndroid OS/Authentication بعد اعتماد الشكل كله فقط.

## مهم — مشروعان مستقلان

| الموضوع | KNOUX AI الأساسي (MiniMax) | KNOUX AI Pro (DeepSeek) |
|---|---|---|
| مستودع GitHub | `daynightae-cmyk/KNOUX-AI` | `daynightae-cmyk/KNOUX-AI-Pro` |
| فرع الدمج | `main` | `master` |
| Windows إن كان متاحًا | `D:\KNOUX-AI` | `K:\KNOUX-AI-Pro` |
| Linux Mobile | `/root/workspace/KNOUX-AI` (مستقل ولا يتزامن تلقائيًا) | لا تفترض وجود نسخة موازية |
| المرحلة الآن | تطابق بصري كامل مع الصور الثمانية، صفحة وراء صفحة | استكمال هوية DeepSeek الذهبية والبنفسجية على جميع الشاشات |
| Stage 2 | المحركات والـOS/Authentication بعد موافقة صريحة | المحركات والـOS/Authentication بعد موافقة صريحة |

**لا تخلط كود أو أسرار المشروعين ولا تعتبر إتمام Visual Screen إثباتًا لعمل Android Service Engine.**

## الحرية الإبداعية المطلوبة
شيل القيود التي تمنع تصميم واجهات جميلة أو مكونات مشتركة أو تغيير تخطيط الكروت بصورة أذكى. ما تمنعش الوكيل من تعديل طبقة الواجهة لتصل للتصميم النهائي. لكن حرية الإبداع مش معناها مسح شغل فريد، أو قتل وكيل شغال قبل تسليم آمن، أو خلط المشروعين، أو تزييف صورة Screenshot أو PASS. المطلوب تصميم عالمي **مع إثبات بصري مباشر**، مش حراسة تعطل التنفيذ.

## ما تم في هذه الحزمة وما لم يتم
**تم:** إعادة قراءة المصادر المرفوعة، إعداد حزمة تصميم وخرائط 100 خدمة و50 ميزة، نسخ وثيقة M00–M15 الأصلية، إعداد وثيقتي OS/Auth وE2E للمرحلة القادمة، وتجميع الصور الثمانية الأصلية.

**لم يتم بهذه الحزمة:** تعديل كود Android، تشغيل الوكلاء، الدمج إلى GitHub، اختبار E2E، منح Entitlement أو تأكيد نجاح OAuth. هذه الملفات جاهزة للإرسال للوكيل؛ ليست شهادة بأن التطبيقات اكتملت.
